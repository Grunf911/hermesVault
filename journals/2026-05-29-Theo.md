## What I learned
- A YTA report can be technically delivered and Gmail-verified while still failing Alan’s quality gates; the workflow needs structural validation before sending, not just post-send delivery checks.
- Gmail plain-text extraction can understate what is in the actual HTML report; for validation, inspect the HTML MIME part and count labels, URLs, score lines, and question-ending drafts.
- `x_search` via xAI OAuth/SuperGrok worked for public X discovery in the corrective run and avoided `x-cli`; `x-cli` should remain backup-only when OAuth search works.
- Actual X follow-state is not reliably verifiable through `x_search`; the safer wording is `Existing nurture` / relevant nurture candidate unless an authenticated follow-state path is available.
- Direct Reddit JSON/search can be blocked while RSS, old.reddit, PullPush, or Arctic Shift still provide usable metadata; direct Reddit blocking should not automatically mean “no Reddit targets.”
- Luma’s hourly queue can be quiet for a full day without indicating failure when every run’s pre-script returns zero pages.

## Recommended corrections
- Keep YTA’s pre-send gate strict: do not send the AgentMail report until the X section has the 20-item target when possible, explicit segment labels, required fields, score lines, and the intended question mix.
- Continue forcing `x_search` / xAI OAuth first for X discovery and record `x-cli` usage only as fallback after the configured failure threshold.
- Use the HTML MIME body for report validation whenever the report is HTML/card-based.
- Keep the Reddit helper in the YTA path and require the run to report which Reddit discovery path was used.
- For X nurture targets, avoid claiming verified follow-state unless the workflow has an authenticated source that proves it.
